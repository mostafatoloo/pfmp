# Internationalization

Selectable languages:

| Code | UI copy | Chrome / nav | Tables & user content |
|------|---------|--------------|------------------------|
| `en` | English | LTR | LTR |
| `finglish` | English | LTR | **RTL** |
| `fa` | Persian (partial + English fallback) | **RTL** | **RTL** |

Fonts: **Outfit** for Latin, **Vazirmatn** for Persian/Arabic glyphs (same stack — the browser picks per character).

## Package

`@pfmp/i18n` provides:

- Locale registry (`LOCALES`, `enabledLocales`, `resolveLocale`, `contentDirectionForLocale`)
- Namespaced message catalogs (`messages/en/*`, `messages/fa/*`)
- `createTranslator` / `useT` with interpolation, plural key suffixes, missing-key logging
- Safe fallback to English
- Locale-aware formatting helpers
- `documentLocaleAttrs` → `{ lang, dir, contentDir }`

## Adding translations

1. Add or extend catalogs under `messages/<code>/`.
2. Register in `translate.ts` `catalogs` map.
3. Set `enabled: true` only when the locale should appear in Settings.
4. Prefer logical CSS; use `[data-content-dir="rtl"]` for content-only RTL (Finglish).

## Distinct concepts

| Concept | Source |
|---------|--------|
| UI language | `User.locale` |
| Message catalog | `messagesLocale` on locale definition (Finglish → `en`) |
| Chrome direction | `direction` |
| Content direction | `contentDirection` (tables, study grid, user text) |
| Calendar system | `User.calendarSystem` (`gregory` \| `persian`) — independent of language |

## Dev RTL simulation

```bash
PFMP_FORCE_RTL=1 pnpm dev
```

Forces English messages with full RTL chrome without changing the selected locale.
